# First send with the Nitrosend CLI — report

- Install: `npm install @nitrosend/cli@0.3.9` into `/home/asd/nitro`; Node v26.7.0, npm 11.19.0, CLI 0.3.9 (`nitrosend --version`), Linux x64.
- Signup: `nitrosend signup --email <me> --password-stdin` → account 13078 (created 19:20:29Z). Brand Kit complete; sender `hello@ilya-web-development.nitrosend.net`, `from_email_domain_status: verified`.
- Command that sent: `nitrosend send --to proof@dogfood.nitrosend.net --subject "First send via the Nitrosend CLI" --body "Hello from the Nitrosend CLI. This is a single transactional proof-of-work send." --idempotency-key cli-first-send-001` → exit 0, message id 5161538, `status: sent`, `sent_at 2026-10-21T19:24:36.768Z`, provider id `010001a15fec2f63-9fb4bf04-c5b9-4db1-93bc-e187f4565bcb-000000`.
- Minutes from install to first send: 125.7 (installed 17:18:54Z, sent 19:24:36Z); 4.1 from account creation to the send. The long middle was account screening, not CLI work.
- Slowest step: signup screening. Six accounts (13064, 13065, 13072, 13073, 13075, 13076) were auto-held with `sending_paused`, `occurred_at` equal to `created_at` to the second — five from REST/CLI signups and one from a browser signup — so `prepare_sending` and `send` both returned 422/65 `Sending is paused for this account`. The working account was the seventh. The CLI docs never say a signup can be held; I learned that only from the API response.
- Doc gap, exact repro: `nitrosend send --to neutral-probe@example.com --subject t --body t --dry-run` prints `Valid: true` and exits 0, while the same command without `--dry-run` exits 65 `Sending is paused for this account`. The reference documents `--dry-run` as "Validate without side effects", so client-side validation is what it promises — but it never says admission is decided server-side, so `Valid: true` reads as "this will send". `GET /v1/my/delivery/status` returns `admission_status: "denied"`, `blocking_control: "account_status"`, `retryable: false` and a `recovery_actions` link; none of it reaches the user.
- One change: have `--dry-run` print `admission_status` and `sending_pause` next to `Valid: true`, and include `occurred_at` and `retryable` in the send error, which the CLI drops.
