# First send with the Nitrosend CLI — report

- Install: `npm install @nitrosend/cli@0.3.9` into `/home/asd/nitro`; Node.js v26.7.0, npm 11.19.0, CLI 0.3.9 (`nitrosend --version` → `0.3.9`), Linux x64.
- Signup and sender: `nitrosend signup --email <me> --password-stdin` → account 13078 (created 19:20:29Z). Brand Kit complete; sender `hello@ilya-web-development.nitrosend.net`, `from_email_domain_status: verified`.
- Command that sent: `nitrosend send --to proof@dogfood.nitrosend.net --subject "First send via the Nitrosend CLI" --body "Hello from the Nitrosend CLI. This is a single transactional proof-of-work send." --idempotency-key cli-first-send-001` → exit 0, message id 5161538, `status: sent`, `sent_at 2026-10-21T19:24:36.768Z`, provider id `010001a15fec2f63-9fb4bf04-c5b9-4db1-93bc-e187f4565bcb-000000`.
- Minutes from install to first send: 125.7 (CLI installed 17:18:54Z, sent 19:24:36Z). 4.1 minutes from account creation to the successful send. The long middle was account screening, not CLI work.
- Slowest step: signup screening. Six accounts were auto-held with `sending_paused` (`occurred_at` = `created_at` to the second) across four e-mail domains and two egress IPs, so both `prepare_sending` and `send` returned 422/65 `Sending is paused for this account`. The account that worked was the seventh. Nothing in the CLI docs says a signup can be held or how long it lasts — I only learned it from the API response.
- Defect, exact repro: `nitrosend send --to neutral-probe@example.com --subject t --body t --dry-run` prints `Valid: true` and exits 0, while the identical command without `--dry-run` exits 65 `Sending is paused for this account`. Dry-run never contacts the server, so it cannot see an account-level admission decision, yet it still reports validity and its output is logged by Nitrosend as a successful send.
- One change I would make: make `--dry-run` call `GET /v1/my/delivery/status` and surface `admission_status`/`sending_pause.recovery_actions` next to `Valid: true`, and include the server's `occurred_at` and `retryable` flags in the send error, which the CLI currently drops.
